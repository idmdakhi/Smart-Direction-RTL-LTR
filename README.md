# Smart Direction — تشخیص هوشمند RTL/LTR

افزونه‌ی کروم (Manifest V3) که جهت متن هر بخش از صفحه را بر اساس محتوای واقعی آن تشخیص می‌دهد:
فارسی/عربی/عبری → راست‌به‌چپ، انگلیسی/لاتین → چپ‌به‌راست، و **کدهای برنامه‌نویسی همیشه چپ‌به‌راست** —
حتی اگر داخل یک صفحه‌ی کاملاً فارسی باشند.

---

## نصب (حالت توسعه‌دهنده)

1. این پوشه را همین‌طور که هست نگه دارید (نیازی به build نیست، جاوااسکریپت خام است).
2. در کروم به آدرس `chrome://extensions` بروید.
3. **حالت توسعه‌دهنده (Developer mode)** را بالا-راست فعال کنید.
4. روی **Load unpacked** بزنید و همین پوشه (`smart-direction/`) را انتخاب کنید.
5. آیکون افزونه را روی نوار ابزار کروم پین کنید تا همیشه در دسترس باشد.

روی آیکون یک حرف کوچک (بَج) نشان داده می‌شود: `A` خودکار، `L` همیشه LTR، `R` همیشه RTL،
و خالی یعنی خاموش — بر اساس تنظیم فعلیِ همان سایت.

---

## استفاده

روی آیکون افزونه کلیک کنید تا پاپ‌آپ باز شود:

- **حالت** را برای همین سایت انتخاب کنید (خودکار / همیشه LTR / همیشه RTL / خاموش).
- **آستانهٔ تشخیص RTL** را تنظیم کنید — پیش‌فرض ۴۰٪ یعنی اگر بیش از ۴۰٪ از حروفِ یک بلوک متنی
  راست‌به‌چپ باشند، آن بلوک RTL می‌شود.
- تیک «این حالت را برای همهٔ سایت‌ها پیش‌فرض کن» تنظیم را سراسری می‌کند؛ در غیر این صورت فقط
  روی همین دامنه ذخیره می‌شود.
- «حذف تنظیم اختصاصی این سایت» override محلی را پاک می‌کند و سایت به تنظیم سراسری برمی‌گردد.

## چه چیزی نسبت به نسخهٔ اول عوض شده؟

| موضوع | نسخهٔ قبلی | نسخهٔ فعلی |
| ------ | ---------- | ----------- |
| نحوهٔ اعمال جهت | `element.style.direction` روی **همهٔ** اجداد و اَحفاد به‌طور تکراری | ویژگی معنایی `dir` فقط روی «برگ‌های متنی» (بلوک‌هایی که خودشان بلوکِ تودرتو ندارند) — بدون تداخل و کار تکراری |
| محاسبهٔ نسبت RTL | تعداد کاراکترهای RTL ÷ همهٔ کاراکترهای غیرفاصله (رقم/علامت/ایموجی هم حساب می‌شدند و نتیجه را منحرف می‌کردند) | تعداد حروفِ *قوی* RTL ÷ (حروف قوی RTL + حروف قوی LTR) — رقم، علامت، ایموجی و فاصله نادیده گرفته می‌شوند |
| فیلدهای قابل ویرایش | دست‌نخورده نبودند؛ خطر خراب‌شدن جهت هنگام تایپ وجود داشت | `input` / `textarea` / `[contenteditable]` همیشه نادیده گرفته می‌شوند |
| MutationObserver | با هر تغییر، **کل صفحه** دوباره پردازش می‌شود (۳۰۰ میلی‌ثانیه تأخیر ثابت) | فقط زیردرختِ واقعاً تغییرکرده پردازش می‌شود؛ اسکن اولیه هم با `requestIdleCallback` غیرمسدودکننده است |
| تنظیمات کاربر | پاپ‌آپ وجود داشت ولی به `content.js` وصل نبود (`action` نام‌های ناهم‌خوان `toggleDirection` در برابر `applyDirection`) | پیام‌رسانی کامل popup ↔ content ↔ background، به‌علاوهٔ override به‌ازای هر دامنه در `chrome.storage.local` و پیش‌فرض سراسری در `chrome.storage.sync` |
| بازخورد بصری | فقط یک آیکون ثابت | بَج پویا روی آیکون که حالت فعلیِ همان تب را نشان می‌دهد |
| تشخیص بلوک کد | لیست کلاس‌های محدود، فقط `walk` دستی روی parentها | `closest()` روی یک selector جامع‌تر (شامل `[class*="language-"]`، CodeMirror، Monaco) + `unicode-bidi: plaintext` |
| iframe | پشتیبانی نمی‌شد | `all_frames: true` در manifest |

## محدودیت‌های شناخته‌شده / ایده برای ادامه

- کامنت‌های فارسی داخل یک بلوک کد هنوز به‌صورت خط‌به‌خط RTL نمی‌شوند؛ کل بلوک کد همیشه
  `dir="ltr"` می‌گیرد (این عمداً است، چون سینتکس کد باید LTR بماند). برای پشتیبانی دقیق‌تر
  می‌توان با `TreeWalker` فقط نودهای متنیِ کامنت را جدا پردازش کرد.
- Shadow DOM بسته (`mode: "closed"`) قابل دسترسی نیست (محدودیت خودِ پلتفرم مرورگر است، نه افزونه).
- تشخیص در سطح "بلوک" است، نه کلمه‌به‌کلمه؛ برای پاراگراف‌هایی که واقعاً به‌طور نامتوازن دو زبان
  را قاطی کرده‌اند (نه یک زبان غالب)، الگوریتم Bidi خودِ مرورگر (`dir="auto"`) نتیجهٔ مشابهی می‌دهد
  و این محدودیت ذاتیِ تشخیص در سطح بلوک است، نه باگ.
